# PUBLIC-SAFE OFFLINE HANDOFF STANDARD (2026-10-16)
This file is a stand-alone offline briefing for a general collaboration/creative workflow. It contains no private fishbowl sources or restricted media. It is not a license to reuse artwork or publish a finished video or game.

## Rules to carry offline
- PSA format requested by the project owner: **10 seconds total; ONE clear point; full pause before and after; nothing else.** Pauses are part of the ten seconds. Do not insert a forced four-beat structure or unrelated content. Test the exported duration.
- Game-engine target: **whole playable levels plus full usable asset collections**. Nodes, isolated meshes, concept images and small tests may help, but a final delivered level must include its actual runnable project/scene, imported source assets and dependencies, a navigable/interactive environment and a verifiable end condition appropriate to the level.
- **Every handoff must have an OFFLINE PACKET, not only a URL.** Include `START_HERE.txt` or a recipient-specific standalone TXT, the exact instruction, source/version, allowed scope, bundled inputs or explicit missing-bytes note, dependencies, validation, and a truthful return receipt.
- For media/engine batches include files needed to work without internet and a manifest recording relative path, sizes, checksums, creators, permitted use, and what was tested. Links are supplemental.
- An offline copy is a dated snapshot. When reconnecting, read current orders. A repository post is not proof another assistant read it or that an implementation works.
- Preserve originals, rights, and boundaries; never include restricted or sensitive files in public packages without approval. No implicit posting, merge, access grant or tool execution.

## Portable minimal START_HERE.txt template
PACKET_ID: [unique ID]    VERSION/DATE: [snapshot]
RECIPIENT: [actual account/assistant]    ORIGIN: [authorizing owner]
TASK: [ONE bounded outcome]    PERMISSION: [GO / REVIEW / HOLD]
INSTRUCTIONS: [include all essential steps, not just URLs]
INPUTS INCLUDED: [names, hashes, dependencies; say NONE if none]
INPUTS MISSING: [explicit blockers]
DELIVERABLE: [full usable video/level/asset batch or review]
TEST: [exact verification, actual result or NOT RUN]
RECEIPT: [prepared / transferred / read / tested / accepted; evidence]
NEXT: [one owner and action]

## One visible reading route — portable and reviewable (October 16, 2026)
A contributor should **state what instructions they actually followed, with source/version, scope, and test evidence**, rather than repeatedly ask the owner which document to follow. Where a conflict is found, return the exact disputed statement and a proposed correction so the owner can review that exception. Unknown access or a missing acknowledgment stays UNKNOWN.

Use one **offline common reader/packet** as the entrypoint for each authorized project scope, with the original sources preserved and their creators credited. Archives, Git and cloud copies may be mirrors, not separate competing versions of canon. Keep private manuals/media out of public packs. This public guidance **does not publish or link any private Worldbook, parables manuscript, agent bowls, or archive**. The current project owner decides what material is publicly clearable.

## Alpha reader implementation note — October 16, 2026
The portable reader/navigation and manual Following/Evidence/Wrong? receipt concept is currently **MODEL ALPHA v0.2**, a prototype, **not a deployed bot dashboard or source-of-truth replacement**. Agent reports may be imported/exported locally as **unverified self-reports**; this does not establish that an AI was active, read instructions, or ran a test. Actual assets, source code, manuscripts and permissions remain in their own authorized stores; public Open Crew has no access to the private reader by virtue of this note. The operational goal remains fewer owner questions: show the precise followed source and evidence, then raise only an unresolved wrong turn. Device/offline testing and cross-agent delivery still require actual receipts.
