# TO WORLD — Media Format Canon: Flat HSBS

**Order ID:** MEDIA-HSBS-001  
**Status:** CANON — owner-approved standing crew order  
**Authority:** Isekai Sensei, October 20, 2026, America/Los_Angeles  
**Applies to:** all TO WORLD / TO DOG stereoscopic image and video deliveries, every crew member, fairy, agent, renderer and handoff.

## Required format

**Flat Half-Side-by-Side (HSBS), Cardboard-style.**

- Left half of the frame: left-eye view.
- Right half of the frame: right-eye view.
- Presentation: flat screen.
- Packing: each eye occupies half the frame width; playback restores each eye's original aspect ratio.
- Use this same delivery format for phone/Cardboard and Quest.
- The output remains HSBS unless Isekai Sensei explicitly changes this canon.

A request mentioning Quest does not authorize changing this format. Do not substitute VR180, 360, Over-Under / Top-Bottom, spherical wrapping or equirectangular projection. Do not silently deliver another layout as an alternative.

## Instruction to carry into every production handoff

> Deliver flat Cardboard-style Half-Side-by-Side (HSBS). Left-eye view on the left; right-eye view on the right. Preserve each eye's original proportions at playback. Use the same format for phone/Cardboard and Quest. This is MEDIA-HSBS-001, the owner-approved standing format.

Record the output as `projection: flat`, `layout: side_by_side`, `packing: half_width`, `eye_order: left_right`. Filename conventions do not replace correct pixels or explicit matching player settings. Preserve source-compatible resolution, frame rate and codec choices from the working process; this order does not invent an untested universal export preset.

## Acceptance and evidence

1. Inspect the actual delivered image or decoded video frames for equal left/right halves and correct eye order.
2. Check that matching flat/SBS playback restores the intended proportions, including half-width correction where required.
3. If stereo depth is claimed, verify the source eye views contain appropriate differences. Identical duplicates do not create stereo depth within the scene.
4. Keep the working source and generation process. Existing successful DeoVR playback remains USER-VERIFIED; missing transferred bytes are an artifact-transfer issue.
5. Record file delivery, static inspection, headset playback and recipient acknowledgement separately. Never promise perfect playback on an untested device.

## Precedence and scope

This standing order supersedes conflicting earlier image/video delivery specifications, including earlier Quest format assumptions. Preserve earlier sources and original media as history; a documentation update does not convert or re-export them. Existing interactive game/WebXR implementations are outside this image/video export order.

Every agent must carry this rule into its next relevant authorized task and downstream production brief. Filing it in a bowl does not establish that its agent has read or accepted it.
